Collective Image Lab

The same images, read more than one way.

A browser tool for looking at a room’s worth of images together. Participants load their own images, arrange them by visual similarity or by hue, and open published collections built by earlier sessions. Everything runs in the browser; the page uploads nothing.

01 · Architecture

What is hosted where

The Lab and Collections interface is hosted by GitHub Pages. Participants use Lab to upload and arrange images in their own browser. Published collections are stored as JSON files in the same repository and explored through Collections.

Nothing about this is server-side. Layouts are computed on the participant’s own machine each time they arrange, which is why the arrangement is something they perform rather than a result handed to them.

Images a participant loads into Lab never leave their browser. The page makes no upload of its own. Contributing to a shared collection is a separate, deliberate act — see Contributing images.

03 · Sequence

Running a session

A workable shape for a session, whether you are running one or working through it on your own. The colour of each marker tells you whose images are on screen at that point.

The participant’s own images
A published, shared collection
  1. Everyone generates or gathers images Whatever the brief is — a prompt run through an image model, a set found in the wild, a personal archive. Ask participants to keep the files together in one folder.
  2. Open Lab and load them Drag the folder into Your images, or use the file picker. Nothing is uploaded.
  3. Arrange, and arrange again Run Similarity, then Hue, on the same set. The gap between the two arrangements is usually where the discussion starts.
  4. Compare across the room Participants who ran near-identical briefs rarely get near-identical arrangements. Put two screens side by side.
  5. Open a published collection Switch to Collections and choose a set by name. Now the same two arrangements run over hundreds of images from other groups.
  6. Close on what the arrangement can and cannot see Hue reads colour. Similarity reads visual features. Neither reads subject, intent or provenance — which is the point worth landing.

04 · Arranging

Similarity and Hue

Hue arranges images by average hue. It is fast, deterministic, and handles the full 500-image canvas.

Similarity arranges by computed visual similarity using exact t-SNE. It is the more interesting view and the more expensive one, which is why it is capped lower.

Above 250 images, Similarity is disabled and the interface directs participants to Hue. If a session needs Similarity on a large set, split the images into smaller batches rather than trying to force it.

Hue and Similarity are both calculated from a representative static frame. They analyse appearance, not motion, so an animated GIF is read on the strength of one frame even though it stays animated on screen.

05 · Limits

Supported images and capacity

The recommended maximum is 500 images per collection or canvas. JPEG, PNG, WebP and GIF files are accepted. GIF animations are preserved and remain visibly animated in Lab and Collections.

Collection or canvas500 Split across JSON parts
  • Unreadable or unsupported files are skipped rather than stopping the whole load, and their filenames are reported.
  • Large collections may be divided into multiple JSON parts, kept below GitHub’s browser-upload limit.
  • Very large sets take a moment to arrange. Keep the tab in the foreground while a layout is computing.

06 · Shared sets

Opening a collection

Collections are ordered by creation time, newest first. Once the archive grows beyond six collections, the interface shows the six most recent by default and provides search and Show all collections.

A collection never loads automatically. The participant chooses which set to open.

Collections are named after the images or the seminar theme rather than a date or a class time, so a set stays findable long after the session that made it.

07 · Contributing

Contributing images

Contributing is separate from the lab exercise. Every participant completes the exercise whether or not they contribute images to the shared archive, and it is worth saying so out loud before anyone submits anything.

Images are contributed under CC BY 4.0, with attribution to the module and department that ran the session. To have an image removed, contact the module convenor: it is withdrawn at the next rebuild, and its position is not reused.

08 · Publishing

Getting a collection published

Turning a folder of contributed images into a published collection is done with a separate, access-controlled builder, and the resulting files are committed to the repository by hand. That step is not open to everyone.

If you have run a session and want its images published as a collection, contact the module convenor. You do not need builder access to run a lab — everything in this tutorial works with the public tool alone.
